- 状态：已确认，进入实施
- 更新日期：2026-09-12
- 适用范围：`velock_sync`
- 关联文档：[`TECHNICAL_SPEC.md`](./TECHNICAL_SPEC.md)、[`SYNC_PROTOCOL_V1.md`](./SYNC_PROTOCOL_V1.md)、[`UI_REDESIGN_SPEC.md`](./UI_REDESIGN_SPEC.md)

## 1. 文档目的

本文档重新定义 Velock Sync 的产品边界。核心修正是：格间同步不是“换机助手”的附属功能，而是一套以**远程备份、数据可靠性和灾难恢复**为首要职责的持续同步能力；换机恢复只是恢复场景之一。

Velock Sync 同时提供两类同步：

1. **格间数据备份**：保存格间已加密、已认证的数据副本，保证设备丢失、被盗、损坏、系统故障、误操作或文件误删时仍可恢复。
2. **其他数据同步**：用户主动选择的其他文件夹或数据源，按通用同步盘/网盘的使用逻辑，与一个或多个远端服务双向同步。

## 2. 产品定位

### 2.1 一句话定位

**Velock Sync 是 Velock 的零知识远程备份与恢复伴侣，同时也是支持用户自选数据源和云端 Provider 的通用增量同步工具。**

### 2.2 格间数据备份

格间数据备份是默认主能力，不是换机流程中的临时工具。用户在旧设备上配置一次后，Sync 应持续增量备份；换机、重装、丢失设备或系统损坏后，使用同一个远端空间恢复。

产品必须让用户清楚理解：

- 备份是否开启；
- 最近一次成功备份时间；
- 当前是否有待上传、失败或需要处理的项目；
- 备份目标在哪里；
- 数据是否端到端加密；
- 删除保护和恢复保留期；
- 新设备恢复时下一步应该做什么；
- Sync 本身不能读取或展示格间明文。

### 2.3 其他数据同步

其他数据同步面向不依赖格间账号的通用场景：

- 用户选择手机、平板或电脑上的文件夹；
- 选择一个远端 Provider 作为同步空间；
- 本地与远端增量双向同步；
- 支持新增、修改、重命名、移动、删除、断点恢复和冲突处理；
- 首次创建时生成独立恢复材料；
- 新设备可通过恢复材料重新加入同步空间。

用户心智应与主流同步盘一致：选择文件夹、选择云端位置、开始同步，之后由系统自动在后台保持同步。

## 3. 核心原则

### 3.1 格间数据始终零知识

对于格间数据：

- `velock_codex` 负责业务数据、数据库事务、加密、解密、签名和 Exchange artifact 生成；
- `velock_sync` 只负责发现、配对、传输、完整性校验、游标、重试、恢复和远端保留；
- Sync 不读取格间数据库、明文、主密钥或同步密钥；
- Sync 不解密、不重新加密、不解释业务 payload；
- 内容恢复、删除恢复、冲突解决和业务状态恢复由格间本体完成；
- Sync 负责保证远端副本可靠、完整、可验证，并向用户提供恢复入口和状态说明。

### 3.2 备份优先于换机

任何格间入口、空状态、错误文案和成功状态都必须从持续备份角度表达。换机、重装、新设备恢复只能作为一种恢复路径，不能成为产品主标题或唯一行动号召。

### 3.3 远端不是临时中转站

远端空间是受保护的恢复副本：

- 对象不可变、幂等、可重试；
- commit 完成前不得把批次视为可见；
- 删除先写业务删除操作，再进入可恢复保留期；
- GC 必须满足保留期、Retention Manifest、checkpoint、活跃设备 ACK 和引用检查；
- Sync 不得为了节省空间静默删除尚未安全确认的恢复材料。

### 3.4 通用同步默认非破坏性

- 首次同步不得静默覆盖远端或本地已有内容；
- 大规模删除必须有保护或确认；
- 冲突不得静默丢失；
- 失败重试必须幂等；
- 用户可以选择保留本地、远端或两个版本；
- 恢复口令只在用户明确导出/导入时出现，不进入普通偏好设置、数据库或日志。

### 3.5 一个同步引擎，多类数据集

前台、后台、手动和预约任务必须通过统一的 Profile Dispatcher 执行。新增通用数据集不得复制一套同步主流程。

## 4. 用户与核心场景

### 4.1 格间用户

#### 场景 A：持续远程备份

用户安装 Sync，连接到自己的 WebDAV、Google Drive 或 OneDrive，完成一次格间配对后开启备份。之后只传输新增或发生变化的数据。

验收结果：

- 首次建立完整基线；
- 后续只做增量；
- 用户能看到最近成功备份时间和备份健康状态；
- App 被杀、断网或设备重启后可恢复；
- 远端对象损坏、缺失或冲突时 fail closed 并给出可执行提示。

#### 场景 B：设备丢失或被盗

用户在新设备安装格间和 Sync，恢复格间账号/vault，重新连接同一个远端空间，然后把备份数据回灌给格间。

验收结果：

- Sync 不要求也不会展示格间明文；
- 新设备只下载本地尚未应用的批次；
- 只有格间返回可信 receipt 后才推进已应用游标；
- 用户可以明确知道恢复是否完成，以及未完成原因。

#### 场景 C：设备损坏或重装

与设备丢失相同，但旧设备可能仍会在之后恢复上线。系统必须继续以设备成员、序列和回执判断哪些数据已被应用，不得因为旧设备离线而阻塞普通同步。

#### 场景 D：误删文件或误操作

格间业务侧确认删除后，删除操作进入「最近删除」；远端保留必要的密文对象和 Retention Manifest。用户在格间业务侧发起恢复，Sync 提供可靠的传输路径。

当前产品承诺为：

- 格间业务保留期：30 天；
- 远端 GC 安全缓冲：额外 7 天；
- 只有全部安全条件满足后才能清理；
- Sync 不展示文件级最近删除列表，也不在 Sync 内直接恢复业务内容。

#### 场景 E：换机

换机是场景 B/C 的一种具体表达，不再作为格间首页的主标题。换机引导必须复用同一恢复链路。

### 4.2 通用同步用户

#### 场景 A：把重要文件夹备份到自己的网盘

用户选择一个文件夹，选择一个远端空间，授权后台同步。系统加密文件名与内容所需的元数据及文件内容，并按增量方式同步。

#### 场景 B：两台设备双向同步

两台设备使用同一份恢复材料加入同一个同步空间。任意设备修改后，另一台下载并应用变更。

#### 场景 C：冲突处理

两边都修改时，Sync 保留双方版本。用户选择：

- 保留本地版本；
- 保留远端版本；
- 保留两个版本。

#### 场景 D：新设备恢复

用户在新设备导入恢复材料，选择目标文件夹并连接远端，完成增量下载。

## 5. 功能范围

### 5.1 格间数据备份 V1/V2 必须包含

- 格间 App 可用性检测；
- 一次性配对与设备信任；
- WebDAV、Google Drive、OneDrive 远端；
- 首次完整基线；
- 增量双向传输；
- 上传、下载、checkpoint、commit、acknowledgement；
- 前台、后台、手动和网络恢复触发；
- 设备成员、设备移除和信任撤销；
- 删除保留、Retention Manifest、安全 GC；
- 备份健康、最近成功时间、最近失败原因和下一步动作；
- 新设备恢复引导；
- 恢复过程中不突破零知识边界。

### 5.2 其他数据同步 V1 必须包含

- 用户通过系统目录选择器授权文件夹；
- 创建独立 Generic Vault，不依赖格间账号；
- 密钥引用仅保存到平台安全存储；
- 目录扫描和变化检测；
- 操作批次编译、加密、签名和完整性校验；
- 双向上传/下载、tombstone、checkpoint 和恢复；
- 排除临时文件、符号链接和协议保留路径；
- 冲突保留与三种解决策略；
- 文件夹不可访问、权限撤销和 Provider 重新授权；
- 恢复材料导出/导入；
- 暂停、恢复、立即同步、移除配置；
- 前台、后台和手动触发走同一 Dispatcher。

### 5.3 后续范围

- 照片库；
- 多文件夹归入同一个 Generic Vault；
- Provider 内直接浏览密文同步空间；
- 历史版本浏览；
- 移动端以外的完整桌面体验；
- 百度网盘、阿里云盘等需要 Token Broker 的 Provider。

## 6. 信息架构

### 6.1 主导航

- 同步：备份与同步的数据集；
- 连接：远端 Provider 凭证与目录；
- 活动：运行历史、传输和冲突；
- 设置：全局默认策略、安全、诊断和版本。

### 6.2 同步首页

同步首页必须分为两个明确区域，而不是只显示单一空状态：

1. **格间备份**
   - 始终说明这是零知识远程备份；
   - 无配置时显示「开启格间备份」；
   - 有配置时显示健康状态、最近备份、目标、待处理项和「立即备份」；
   - 恢复/换机入口为次要说明，不作为主按钮。

2. **文件夹同步**
   - 显示用户创建的通用同步配置；
   - 无配置时提供「新建文件夹同步」；
   - 主操作是选择本地文件夹和远端位置；
   - 显示同步状态、最近运行、冲突和暂停状态。

### 6.3 新建同步

`新建同步` 先选择数据类别：

- 备份格间数据；
- 同步文件夹。

不得默认把所有用户都直接送入格间配对向导。

### 6.4 格间备份详情

必须显示：

- 备份状态与最近成功备份；
- 备份目标；
- 后台策略；
- 端到端加密说明；
- 删除保护与保留期摘要；
- 设备成员/授权状态；
- 最近失败的技术详情入口；
- 新设备恢复说明与入口；
- 暂停、继续、立即备份和移除配置。

不得显示：

- 文件名、路径、格间明文；
- 密文内容；
- UUID 前缀作为用户名称；
- 需要 Sync 伪装的「最近删除列表」。

### 6.5 文件夹同步详情

按通用同步盘习惯显示：

- 本地文件夹；
- 远端位置；
- 当前状态；
- 最近同步和下次同步；
- 待上传/待下载数量；
- 冲突；
- 后台与蜂窝网络策略；
- 暂停、立即同步、导出恢复材料、移除配置。

## 7. 状态与文案规则

### 7.1 格间备份状态

- `未开启`：没有备份配置；
- `准备中`：正在检查格间、连接或恢复环境；
- `备份中`：正在传输；
- `已保护`：最近一次备份成功且等待后续变更；
- `需要处理`：授权、远端或完整性需要用户操作；
- `已暂停`：用户主动暂停；
- `无法备份`：配置不可恢复，需要重新配对或重建配置。

不得把「换机完成」作为正常备份状态。

### 7.2 通用同步状态

- `准备中`；
- `同步中`；
- `已同步`；
- `等待网络`；
- `部分完成`；
- `有冲突`；
- `需要授权`；
- `已暂停`；
- `失败`。

### 7.3 安全文案

所有格间入口必须明确：

> Velock Sync 不读取格间明文，也不保存格间密钥；它只传输格间已经加密和认证的数据。

所有通用同步入口必须明确：

> 远端只保存加密后的同步对象；恢复材料是重新加入同步空间的凭据，请妥善保管。

## 8. 恢复与删除保护

### 8.1 格间恢复

- 恢复材料由格间本体管理；
- Sync 负责重新连接远端、识别同步空间、下载缺失批次并交给格间；
- 只有格间处理后签发可信 receipt，Sync 才推进 applied cursor；
- 如果远端身份、成员签名、序列或对象完整性异常，stop/fail closed；
- Sync 不提供绕过格间业务验证的恢复能力。

### 8.2 通用同步恢复

- 创建 Generic Vault 时生成独立 root key；
- 导出恢复材料时必须要求用户设置恢复口令；
- 恢复材料使用口令包裹 root key，并携带重新加入所需的信任信息；
- 普通偏好设置、SQLite、日志和远端对象不得保存恢复口令或明文 root key；
- 导入恢复材料后创建新的本地设备签名身份，不重用其他设备私钥。

### 8.3 删除保护

- 通用同步使用 tombstone 保存删除意图；
- 移动端首次发现大规模删除时不得直接静默删除；
- 格间删除使用 Velock 业务语义和 Retention Manifest；
- GC 不得清理仍被活跃 revision、checkpoint、retention hold 或未确认设备引用的对象。

## 9. 非功能需求

### 9.1 可靠性

- 同一批次重复执行不产生重复对象；
- 进程退出后可恢复；
- 上传成功但状态未持久化时可安全重试；
- 下载未完成前不得暴露给数据源；
- 任何“已完成”状态必须可追溯到耐久运行记录。

### 9.2 安全

- 凭据、密钥和恢复口令不进入普通偏好设置、SQLite、日志和远端清单明文；
- Provider 只接收逻辑 key 和字节流；
- 路径穿越、未知生产者、签名/hash 错误、非法版本和伪造 receipt 必须 fail closed；
- 诊断导出默认脱敏。

### 9.3 性能

- 大目录扫描分页、流式处理，不在 UI 线程全量 hash；
- 大文件流式上传/下载；
- 移动端默认限制并发；
- 大批量按 operations/bytes 限额切成批次；
- 支持 checkpoint 和增量恢复。

### 9.4 可测试性

- Sync Core 不依赖 Flutter Widget；
- Provider 有统一契约测试；
- Generic Vault 使用固定测试向量；
- 前台/后台 Dispatcher 组合一致性有测试；
- 恢复、GC、冲突和删除保护必须有回归测试。

## 10. 成功指标

- 格间备份 7 日成功运行率；
- 距最近一次成功备份的时长；
- 首次完整备份成功率；
- 恢复演练成功率；
- 增量运行不重复上传率；
- 通用同步收敛率；
- 未解决的删除/修改冲突数；
- 数据丢失事故数，目标为 0；
- 静默冲突覆盖数，目标为 0；
- Provider 契约测试通过率。

不得采集业务明文、文件名、路径、凭据或格间内容作为产品指标。

## 11. 验收标准

1. 同步首页同时体现「格间备份」与「文件夹同步」两类能力。
2. 格间空状态不再把换机助手写成主定位。
3. 已有 `velock-managed` Profile 不需要迁移即可继续运行。
4. 格间备份详情可见最近成功、目标、后台策略、恢复入口和安全说明。
5. 格间恢复仍由格间本体完成业务恢复，Sync 不展示明文。
6. 用户可以创建通用文件夹同步配置。
7. 通用同步完全复用 SyncProfileRepository、Dispatcher 和 Sync Core。
8. 通用同步默认端到端加密，并支持恢复材料导出/导入。
9. 通用同步冲突支持保留本地、远端和双方。
10. 后台调度同时执行格间备份和通用同步。
11. 既有格间同步测试不回归。
12. `flutter analyze` 无新增问题，相关单元/组件测试通过。

## 12. 明确非目标

- 把格间主密钥或业务数据库复制到 Sync；
- 在 Sync 内浏览、编辑或恢复格间明文；
- 用 Sync 代替格间冲突处理；
- 运行时下载并执行第三方数据源插件；
- 云盘之间不落本地的直接搬运；
- 首版通用同步覆盖照片库、任意 App 沙盒或整个文件系统；
- 保证 iOS/Android 后台任务在精确时间执行。

# 通用端到端加密 Vault 恢复

本流程只适用于由 Velock Sync 创建的 Generic Vault。它不能导出、恢复或替代 Velock App（格间）的密钥与设备授权。

## 恢复材料

`VaultRecoveryPackageCodec` 将 32 字节 Vault Root Key 包装为 `VLSR1.` 开头的恢复包：

- PBKDF2-HMAC-SHA256，默认 600,000 次迭代和随机 16 字节 salt；
- AES-256-GCM，随机 12 字节 nonce，固定版本化 AAD；
- 包中不含明文 Root Key、Provider Token、设备私钥或业务数据；
- 包解析限制 KDF 迭代次数与各字段长度，错误口令和篡改均只返回通用失败。

恢复包本身是高敏感材料；口令必须通过与恢复包不同的受保护渠道传递。不得把任一材料上传到远端对象存储、SQLite、偏好设置、日志或崩溃上报。

## 加入已有 Vault

1. 在已有设备上使用根密钥引用导出恢复包，并设置强口令。
2. 在新设备导入恢复包和口令；服务把解出的 Root Key 写入 `VaultKeyStore`，调用方只取得新的不透明 key reference。
3. 配置同一远端位置并通过已知的 `vaultId` 验证 `protocol.json`。
4. 新设备生成自己的 Ed25519 签名身份；由显式恢复/配对流程在本地写入可信设备记录，再发布不可覆盖的已签名成员描述。
5. 仅在协议与本地信任均验证后，下载 checkpoint 和后续增量。

已有同步文件夹的“钥匙”操作会要求两次输入恢复口令，并且只在一次性窗口中显示恢复包；应用不会自动复制、上传或保存该字符串。关闭窗口后需要重新生成恢复包。

远端出现的成员描述永远不会自动授信。恢复包只传递 Vault Root Key，不授予某个远端成员权限，也不复制已有设备的签名私钥。

## 产品边界

应用已提供恢复包和口令的手工加入入口；它会要求用户选择已有远端连接、输入 Vault ID、再选择本地目录。首版是否额外提供二维码设备配对仍是 PRD 待确认项。无论使用何种入口，都不得把恢复包或口令写入应用日志。

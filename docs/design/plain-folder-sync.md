# 明文文件夹同步（同步位置）设计（2026-09-27）

状态：用户已确认方向。用户原话要点：**「这里根本不需要加密，就单纯的同步软件」**；每个「同步位置」= 本机某个文件夹 ⟷ 远端某个目录，可以添加多个（远端可以在不同连接）；方向与冲突**按市面产品做法**处理（用户已同意默认：双向同步 + 冲突保留两份 + 首次绑定两边都有内容时由用户选择合并/本机覆盖/远端覆盖）。

本文件是这一轮改造的唯一设计依据。旧「加密对象同步」（`SyncDatasetKind.selectedFolder`）不改协议、不删除数据，仅停止作为新建入口，见 §7。

## 1. 产品定位

- 「文件同步」= 普通同步盘：本机文件夹与远端目录保持同样的文件名、目录结构与内容，远端用 WebDAV 客户端/NAS 文件管理器就能直接看到和修改。
- 不做端到端加密、不做签名链、不做版本向量；远端目录就是用户的文件。
- 「格间」路径不变：格间备份继续使用零知识加密协议，两者互不影响。
- 同步位置可以有很多个，每个绑定一份「本机文件夹 + 远端连接/目录」，各自独立运行、独立状态。

## 2. 概念模型

```
同步位置（SyncLocation）
├── 本机文件夹   localRootReference + accessKind + localDisplayName
├── 远端位置     connectionId + remoteRootSegments（解码后的相对路径段）
├── 方向         bidirectional | uploadOnly | downloadOnly
├── 冲突策略     keepBoth | preferLocal | preferRemote
└── 状态/后台策略/创建时间/最近运行统计
```

- 一个同步位置对应一个 UUID `profileId`，与格间/旧加密配置共用 `sync_profiles` 表，`kind = plain-folder`。
- 不需要 vault/密钥/恢复包：远端是明文，另一台设备只需「添加同步位置」并选择同一个远端目录。
- 同一个连接可以被多个同步位置使用（不同远端子目录）；同一个本机文件夹被两个同步位置绑定必须被拒绝。

## 3. 方向与冲突（市面对照）

| 本产品 | 市面同类 | 语义 |
| --- | --- | --- |
| 双向同步（默认） | Syncthing「发送和接收」、Resilio 双向、Dropbox/OneDrive 同步盘 | 两边改动互相传播；同路径同时改 → 冲突 |
| 仅上传（本机 → 远端） | Syncthing「仅发送」、FolderSync 单向上传 | 本机是唯一真值：本机改动上传、本机删除删远端、远端被删会重新上传；远端独有的文件不下载也不删除 |
| 仅下载（远端 → 本机） | Syncthing「仅接收」、FolderSync 单向下载 | 远端是唯一真值：远端改动覆盖本机、远端删除删本机、本机对已同步文件的改动会被覆盖（回滚）；本机独有、从未同步过的文件不删除 |

冲突策略（仅双向同步生效，默认 `keepBoth`）：

- `keepBoth`（默认，Dropbox/Syncthing 的做法）：远端版本写入原名，本机改动版本另存为 `名称 (本机冲突 2026-09-27 14-03).扩展名`，两个版本都会保留并继续同步；冲突记录进数据库并在界面显示数量。
- `preferLocal`：本机版本覆盖远端。
- `preferRemote`：远端版本覆盖本机。

不做「每个冲突都弹窗打断」：后台同步必须能自己收敛；冲突不是静默丢失（保留两份），并且始终在同步位置详情里可见。

## 4. 同步算法

### 4.1 基线

每个同步位置在本地数据库保存「上次同步后的两端状态」：

```
relative_path -> { kind, local_size, local_mtime, remote_size, remote_mtime, remote_etag, synced_at }
```

比对只使用 **大小 + 修改时间**（可选 etag）：这是 Syncthing/FolderSync 的默认做法，不需要全量读取内容。文件大小相同、mtime 相同即视为未变化。

### 4.2 逐路径判定（有基线）

| 本机 | 远端 | 双向 | 仅上传 | 仅下载 |
| --- | --- | --- | --- | --- |
| 未变 | 未变 | — | — | — |
| 改了 | 未变 | 上传 | 上传 | 用远端覆盖本机 |
| 未变 | 改了 | 下载 | 上传（本机为准） | 下载 |
| 改了 | 改了 | 冲突 → 策略 | 上传 | 下载 |
| 删除 | 未变 | 删远端 | 删远端 | 恢复本机 |
| 未变 | 删除 | 删本机 | 重新上传 | 删本机 |
| 删除 | 删除 | 清基线 | 清基线 | 清基线 |

### 4.3 没有基线（首次同步 / 新文件）

- 只有本机有 → 上传（`downloadOnly` 下保留不动，不删除）。
- 只有远端有 → 下载（`uploadOnly` 下保留不动，不删除）。
- 两边都有：
  - 大小相同且 mtime 在容差（2 秒）内 → 视为同一文件，直接建立基线；
  - 否则按首次同步策略：`merge`（默认）= 按冲突处理方式处理（默认 `keepBoth`，即本机版本另存冲突副本 + 下载远端版本；若用户把冲突方式改成“以本机为准/以远端为准”，首次同步同样遵循该选择并记录冲突）；`localWins` = 直接上传本机；`remoteWins` = 直接下载远端。
- **首次同步绝不执行删除**：没有基线的路径永远不会被判为「删除」。

### 4.4 删除保护

沿用现有阈值（最多 1000 项或基线的 20%）：超限时本次运行**不执行删除**，只做上传/下载，并在结果里返回「待确认删除 N 项」。被扣下的删除**保留基线行**，否则下一次运行会把文件当成新文件重新下载，等于静默撤销用户的删除。界面明确显示，用户确认后再次运行（带 `allowDeletions: true`）才真正删除；该参数只对这一次确认生效。

### 4.5 执行顺序

1. 建立本机/远端目录（空目录也要镜像）
2. 处理删除（先远端后本机，受 §4.4 约束）
3. 上传（本机 → 远端，流式，先传后删旧的同名临时内容不需要，直接 PUT 覆盖）
4. 下载（远端 → 本机，先写临时文件再原子替换，流式）
5. 写入新基线；记录统计与冲突

## 5. 远端布局

- 远端目录内容 = 本机文件夹的**逐文件镜像**：`<用户选择的远端目录>/<相对路径>`。
- 不写入任何 marker/清单文件（用户要求「单纯的同步软件」）；同步位置的身份只保存在本机配置里。
- 远端目录为空 → 首次同步即上传；远端目录已有内容 → 视为可合并（§4.3），不删除远端任何东西。
- 只支持 WebDAV 连接（NAS/Nextcloud 等）。OAuth 云盘（Google Drive/OneDrive/百度/阿里）在明文镜像语义下需要新的文件级适配，本轮不开放，界面明确说明。

## 6. 数据模型与数据库

新增 `SyncDatasetKind.plainFolder`（持久化值 `plain-folder`），profile 走通用 `SyncProfileEnvelope`（`vaultId` 对明文同步无意义，按 kind 放宽校验）。

数据库 schema v12 新表：

```sql
mirror_entries(profile_id, relative_path, kind, local_size, local_mtime,
               remote_size, remote_mtime, remote_etag, synced_at,
               PRIMARY KEY(profile_id, relative_path))
mirror_conflicts(conflict_id PK, profile_id, relative_path, detected_at,
                 resolution, detail)
mirror_run_stats(run_id PK, profile_id, started_at, finished_at,
                 uploaded_file_count, downloaded_file_count,
                 deleted_local_count, deleted_remote_count,
                 conflict_count, held_deletion_count, bytes_transferred)
```

运行记录复用既有 `sync_runs`（`sync_profile_runner` 的 run 表），这样首页状态、后台调度、活动页都能直接复用。

## 7. 与旧加密「文件同步」的关系

- 旧 `kind = selected-folder` 配置继续可见、可运行（现有 runner 不动），但：
  - 「添加同步位置」不再创建加密配置；
  - 文件同步首页把明文同步位置作为主列表，旧加密配置折叠在「旧版加密同步（不再新增）」区域，并说明远端是加密对象、需要恢复包。
- 旧配置的远端数据是加密对象，**不能**转换成明文镜像，本轮不做自动迁移；用户可自行删除旧配置后重新添加明文同步位置。

## 8. 界面结构

文件同步（底部 tab）：

1. 同步位置列表：每张卡片显示
   - 标题（默认 = 本机文件夹名，可改名）
   - `本机：<文件夹名>` 与 `远端：<连接名> · <路径>` 两行
   - 方向徽章（双向 / 仅上传 / 仅下载）+ 状态（未同步 / 正在同步 / 已完成 / 失败 / 有待确认删除 / 有冲突）
   - 最近一次统计（上传/下载/删除/冲突数量与时间）
   - 主按钮（立即同步 / 处理问题）+ 进详情
2. 「添加同步位置」三步向导：
   - 第 1 步 本机文件夹（系统选择器，显示文件夹名）
   - 第 2 步 远端位置（选连接 → 浏览目录 → 可新建文件夹 → 选中）
   - 第 3 步 同步方式（方向三选一 + 冲突策略三选一）+ 首次同步说明 → 「创建同步位置」
3. 同步位置详情：
   - 同步位置：本机文件夹（可更改，更改后重建基线并提示）、远端文件夹（可更改）
   - 同步方式：方向、冲突策略（改完立即生效）
   - 运行：立即同步、暂停/恢复、最近统计、待确认删除、冲突列表
   - 后台与网络：沿用现有后台策略开关
   - 删除同步位置（只删本机配置，不动两端任何文件，弹窗写清楚）
4. 「检查云端位置」不再是主流程：远端目录在添加向导里就选好并做一次可写预检；存储类失败只剩真正的故障恢复入口。

## 9. 安全与措辞边界

- 界面必须明确说明：**远端目录是明文**，任何能访问该目录的人/服务都能看到、修改文件；这与格间备份的零知识承诺不同。
- 不做「已备份」承诺：同步完成只说「本次同步完成：上传 N、下载 M、删除 X」，并显示时间。
- 本机删除会被传播到远端（双向/仅上传），首次同步与超阈值删除有保护；界面在方向选择处明确写出删除语义。

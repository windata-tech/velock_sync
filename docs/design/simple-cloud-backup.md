# 普通用户云备份 UI 第一轮重构设计（2026-09-25）

## 1. 基线与范围

- 原 Sync `main` 备份：`a1b7c6451afa40ce1f43de056c2288daa72ab413`。
- 格间 `main` 备份：`c5ba1ba2fa34c1f8e6935c9a1515acb2d42c2691`。
- 两个仓库服务器均有 annotated tag：`backup/20260925-before-simple-sync`。
- Sync 与格间的交付分支均为 `codex/simple-cloud-backup`；实际提交以各仓库该分支记录为准。
- 本轮目标是默认界面不要求普通用户理解内部协议名词、技术计数和内部对象，而不是改变同步协议、恢复验证或数据格式。既有 runner 仍是正式执行路径。

## 2. 用户可见的产品边界

- **格间负责**：加解密、原账号恢复，以及实际应用业务数据；恢复卡和任何格间秘密只在格间中处理。
- **Sync 只负责**：把格间产生的数据对象传输到用户选择的远端，并从远端取回对象。此格间专用流程不向 Sync 提供格间恢复卡密码、私钥或解密材料。普通文件同步仍由独立流程管理自己的加密与恢复。
- 主按钮、状态标题和说明来自真实状态，不把以下任一事件表述成“完整备份成功”或“完整恢复成功”：用户完成授权、建立连接、创建配置、上传一个对象、下载一个批次、runner 返回完成。
- 状态通过 `BackupPresentation` 从 profile、run、pending、冲突和格间可用性投影得到；它是展示层，不是新的同步真值。缺少完成回执、历史不连续、blob 不完整、签名或历史连续性失败时，状态必须失败关闭并要求处理。
- 本轮不放松原签名、历史连续性、blob 完整性或完成回执门禁。

## 3. 信息架构与导航

三个主入口固定为：

1. **格间**：云备份首页、首次设置、真实状态摘要、恢复入口和连接详情。
2. **文件同步**：只展示普通文件夹同步；不混入格间 profile，也不显示格间恢复入口。
3. **设置**：云账号/保存位置、传输记录、后台与高级设置的入口。

技术计数、批次/数据块/成员授权/UPSERT/SEQ/对象内部状态放入“详细记录与诊断”等二级页面。需要用户处理的授权、冲突、待批准设备、存储安全失败不能因此隐藏：首页和详情仍直接显示状态、数量和下一步动作。

## 4. 首次设置文本流程

1. 格间提示用户准备恢复卡并完成格间授权。
2. 用户选择已有云端位置或新增云账号/目录。
3. Sync 先再次验证格间签名授权，再对所选位置做安全检查。
4. 进入原有真实 runner，由既有协议路径执行实际传输。

授权、保存连接或通过预检都不是“首次备份完成”。只有真实 runner 的完成状态与现有完整性门禁同时成立时，界面才能显示传输已完成；即使如此，也不得把它扩大解释为六类业务内容已经存在可验证的完整云端摘要。

## 5. 恢复文本流程

1. 用户先在格间中找回原来的账号；Sync 不接收恢复卡密码。
2. 格间给出签名授权。
3. Sync 只读检查原保存位置中、与签名授权内可信 producer 和原账号匹配的候选历史。
4. 候选通过既有 runner 的签名、历史连续性和 blob 校验。
5. 下载内容回到格间，由格间解锁并应用到实际业务数据。

候选发现的定义仅为：在正确位置找到可信 producer 的 commit 入口。它是候选，不是完整验签、不是历史完整性证明、不是内容验证、更不是恢复成功。空目录、其他账号、不受信 producer、只有 checkpoint 或部分批次都不满足恢复候选门禁。

返回行为必须保留当前恢复上下文：从恢复流程进入云端新增页面再返回时，restore intent 和已批准授权保留；回到已有设置页面后自动继续，不要求用户重新授权或重新选择恢复。`returnTo` 只接受已知内部流程白名单，不接受任意 route、URL 或带额外查询参数的地址。

## 6. 云端连接与 OAuth 体验

- 普通用户默认看不到 Client ID、Token 或 root/起始文件夹 ID。Google Drive/OneDrive 的主流程是登录、浏览器授权和选择保存位置。
- 应用未配置公开 OAuth 注册时，界面明确说明“此版本暂未开通”，强调不是用户账号故障，并提供“选择其他保存位置”。
- 自定义构建仍保留开发者配置，但折叠在“开发者配置”中；公开 Client ID 只在用户显式保存后生效，输入过程中不触发页面替换。界面不要求 Client Secret。
- “更多设置（可选）”中的起始文件夹 ID 是高级入口，默认折叠；普通用户不需要理解或填写它。

### 跨 App 打开契约

格间使用 `velocksync://app/open` 仅唤起 Sync，不能将正在进行的设置/恢复流程强制跳回首页。Android 注册独立的严格 URI filter，iOS/macOS 注册 `velocksync` scheme；iOS/Android 关闭 Flutter 内建自动 deeplink 路由，既有 `app_links` 继续单独处理 OAuth 回调。平台注册目前只通过静态契约验证，冷/热启动仍需原生设备验收。

## 7. 云端位置预检

首次设置使用随机、无敏感内容的 probe：

- 仅以 `ifAbsent` 创建，避免覆盖同名对象。
- 写后读回并逐字节校验。
- 只删除本次成功创建且由本次预检拥有的 probe；碰撞或其他人的对象不删除。
- 校验失败、超时或取消时失败关闭并清理自己的 probe。
- 恢复探测只读：只查询已批准 vault 下可信 producer 的 commit 前缀，不写远端，也不会把空目录当作新 vault。

预检只证明所选位置具备本轮所需的基本读写行为，不证明完整备份存在，也不替代 runner 的签名、历史和内容校验。

## 8. 格间页摘要与迁移

格间页已改为面向用户的云备份摘要：主状态、恢复卡入口和需要处理的事项优先展示；管理授权与详细诊断使用右箭头进入独立页面，不在首页原地展开；UPSERT/SEQ 等协议细节只在诊断页显示。恢复卡入口、待批准设备和冲突仍显著可见。相关兄弟仓库中的格间页面改动按同一责任边界工作，本设计不重复或扩大协议结论。

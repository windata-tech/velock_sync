# 云端安全写入错误的可执行入口（2026-09-26）

## 问题

上一轮只统一了首页卡片，`BackupAction.manage` 仍从首页进入相同概览，再从概览进入普通管理页。那里只有恢复包/后台/蜂窝/删除，并不能处理安全写入失败。不能把这种导航称为有效错误处理。

## 修改与约束

- 安全写入失败和目录不可写使用专用 `BackupAction.checkStorage`，首页、详情均一步进入 `BackupStorageHelp`。卡片改为“云端位置需要检查 / 检查保存位置”，不再模糊提示“有一件事”。
- 页面显示当前连接名和任务的实际 scope 路径。普通文件任务使用连接根，格间使用 remoteRootSegments；不会猜测/覆盖目录。
- 打开页面仅读取连接，不进行远端检查、同步或错误清理。明确这与恢复包/后台开关无关。
- “重新检查此位置”显式调用已有 BackupDestinationService：非业务 probe 的安全创建、读回、清理；不会上传用户文件、变更目录或把旧 run 标记成功。保留 ifAbsent、只删自有探针等门禁。
- 成功只说“位置检查通过，尚未同步”，用户另点“开始同步”才走真实 runner；真实完成仍由 runner 决定。失败持久显示原因，禁用开始同步，没有自动重试。
- 浏览入口只打开当前连接目录，明确浏览不自动选择或同步。
- 如检查仍失败，说明 NAS 入口可能只读及当前已有文件任务目录迁移尚未支持，不引导修改格间共用连接、删除数据或调整无关开关。此处没有冒充提供自动迁移/服务器修复能力。
  - **已被后续取代（2026-09-26）**：文件同步任务的“选择可写入文件夹”闭环已实现，见 `2026-09-26-file-sync-folder-relocate.md`；本文件中“尚未支持迁移目录”的描述不再代表当前版本。

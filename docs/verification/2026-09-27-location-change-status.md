# 换目录后旧失败不能代表新目录状态

## 现场证据

用户 17:43 截图中路径为 `/USB_HDD_8T/111`，卡片仍写「云端备份不完整」，失败时间为 17:34。

只读核对模拟器数据库：配置于 17:42:52 更新为 `/111`；最新运行仍是 17:34:38 的 `remote.velock_history_incomplete`，其后没有新的运行。因此截图展示的是换目录前的失败，不是 `/111` 刚被验证失败。

## 修正

- 显式保存格间备份位置时，在同一次 profile 保存中记录 `dataset.locationChangedAt`。不使用通用 updated_at，以免后台设置、暂停/恢复等修改被误认为更换目录。
- 首页 summary 与详情页同源读取该标记。最近运行开始时间早于位置保存时间时，显示「保存位置已更改」，说明新位置尚待检查，主操作为「检查并备份」。
- 此标记仅服务 UI；不删改旧运行、不清 cursor/错误、不跳过任何完整性门禁，也不把配置保存当备份成功。
- 新运行开始后按真实运行状态显示；再次失败仍进入原错误处理。运行中、授权、冲突、配置阻断、暂停及格间恢复文件未准备好的优先级保留。
- JSON 往返、copyWith 和批准新设备后重建 profile 均保留标记。旧配置不含字段仍可读取；不猜测或回填旧配置的更改时间。

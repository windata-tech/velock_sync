# 建立新备份成功记录缺失（2026-09-27）

## 现场与根因

用户在 22:40 完成新远端目录备份，记录页却只有「无需传输」和旧失败。
只读核对现有 iPhone 17 Pro Max 的 state.db：profile 已保存 `USB_HDD_8T/ttt`，`locationChangedAt=2026-09-27T14:40:39.983556Z`，currentSnapshotId 已写入；22:40:40 的 completed 是随后普通 runner 的空增量检查。快照上传流程没有写 sync_runs 或 transfer_jobs，因此列表确实缺了一条。

## 修复

- schema 13 为 sync_runs 增加可选 rebuild_json；独立保存请求开始时间、原完成时间、目标位置、签名清单的快照加密对象数量/总字节，以及是否补回记录。
- 快照上传和完整远端回读均通过、授权重新检查完成后，profile CAS 与成功记录在同一 SQLite transaction 提交。记录写失败则位置更新回滚。成功记录身份绑定 profile+snapshot，重复调用不复制。
- 列表显示「新备份已建立」，详情显示保存位置及「已校验的备份内容」。计数是快照 part/blob/manifest/commit，明确不是业务文件数或重试时实际网络上传流量；恢复文件与目录归属标记不纳入这个快照计数。普通空增量依旧「无需传输」。
- 查看已有快照 profile 详情时，可修复旧版遗漏：持久 job 与当前 profile 必须精确匹配当时的成功切换结果；校验格间签名回执、签名清单及其 hash 绑定。只准备、不同目录/身份、伪造回执或证据缺失不补成功。全程无远端访问、不触发上传，不修改有效 profile 字段。补回记录保留原完成时间并在详情说明来源。

84 项相关测试通过；新增覆盖真实上传完成的数量/字节、重试幂等、旧证据补回/拒绝、记录插入失败原子回滚、陈旧或已删除配置拒绝、中英文完成明细。覆盖既有重建按钮导航与普通空运行口径。改动范围 analyze 无问题。

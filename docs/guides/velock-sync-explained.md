# 格间与 Sync：从保存数据到云端备份，再到新设备恢复

适用范围：目前的格间专用备份流程，以 Apple 设备上的格间 + Sync、WebDAV 保存位置为主。普通「文件同步」是另一个功能，不按本文的加密交接流程工作。本文根据 2026-09-27 的实现整理。

## 一、两个 App 各做什么？

可以把格间理解为「整理资料并上锁的人」，把 Sync 理解为「运送上锁资料的人」。

| 参与者 | 负责什么 |
|---|---|
| 格间 | 保存你的文件、照片、账号、信用卡、备注等；准备备份内容，加密和签名；恢复时解密、把数据放回实际使用的位置。 |
| Sync | 连接你的 NAS 或其他受支持的云端位置；上传、下载加密备份；检查内容是否完整、来自可信的格间设备。 |
| NAS / 云端目录 | 存放加密备份文件，让另一台已授权设备能够取回。 |
| 恢复卡 | 帮你在格间找回原账号的恢复信息。它不是业务数据备份本身，也不替代云端文件。 |

Sync 需要 NAS 登录信息，但不会向你索取格间的恢复卡密码或账号解密秘密。数据正文的加密、解密由格间完成。

## 二、第一次配置：先取得许可，再选择地方

1. 在格间准备并妥善保存恢复卡。
2. 按向导让格间允许 Sync 连接。这个许可限定了它能为哪个账号、哪台设备传输数据。
3. 在 Sync 添加云端连接，选择一个实际可用的文件夹。只连接到 NAS 根目录，不代表已经选好了可写的备份位置。
4. Sync 检查连接和保存位置。首次备份的检查会使用随机、无敏感内容的小测试文件，并清理自己创建的测试内容。
5. 开始真正的备份，把格间已经准备好的内容传到所选位置。

「已允许连接」「连接成功」「文件夹可用」只代表准备工作完成，不能单凭其中一个就认定数据已经备份。临时授权过期时需要重新授权，但不需要因此乱换备份目录。

## 三、平时新增一个文件，怎样到达云端？

例如，你在格间加入了一张照片或一个文件：

**你保存内容 → 格间记下变化 → 格间准备加密包 → Sync 上传 → 检查传输结果 → 留下记录。**

更具体地说：

1. **先保存到格间本机。** 这时你能打开文件，不代表云端已经有它。
2. **格间准备变化内容。** 连续修改会短暂合并处理，避免每次轻微操作都立刻打包；当前部分写入路径采用约 400 毫秒的合并等待。这只是触发安排，不是保证 400 毫秒内完成所有备份。
3. **把内容加密，并附上来源证明。** 文件或照片的数据块，与“哪条资料发生了什么变化”的记录可能分开存放。
4. **Sync 取走已经准备好的包。** 你可以点「立即备份」；自动传输则受设置、网络和系统后台限制影响。
5. **传到云端并按协议发布。** 它会避免覆盖已有不可变备份，检查需要的记录和附件。未完成的部分不能冒充完整备份。
6. **留下传输结果，并向格间交接结果。** 以后可以区分哪些内容已经发布、哪些还需要处理。

格间必须有机会运行，才能准备新变化。iOS 也可能暂停后台 App，所以不能理解为“刚改完，任何时候都保证马上到云端”。稳妥的操作仍是：在格间保存并确认内容可打开，再切到 Sync 查看备份结果。

## 四、云端为什么会有许多看不懂的文件？

一个用户文件，不一定只对应一个云端对象。一批备份通常包含：

- **加密内容**：文件、照片等的实际数据。
- **加密变化记录**：记录新增、修改、删除等信息。
- **清单与完成标记**：说明这批内容有哪些部分，帮助判断有没有缺失。
- **辅助信息**：恢复文件、授权信息、进度检查点等，按流程需要保存。

你不需要手工操作这些内部文件。只复制其中几份，或觉得文件名陌生就删除，都可能使备份不完整。

本次检查的完整快照为 **11 个对象、约 6.6 MiB**：8 个加密附件数据块、1 个记录包、1 个清单、1 个提交标记。11 不是“格间里有 11 个文件”；其中约 99.6% 的体积来自附件数据块。恢复文件等辅助对象不包含在这个快照计数内。

## 五、换远端目录，要分清两种操作

**找回原来的备份目录**：原备份仍在，只是之前选错了位置。选择真正存放原备份的目录，确认保存；这本身不会复制、迁移或删除两边数据。继续备份时仍要检查原历史是否完整。

**在新空目录建立新备份**：原备份找不到，或你明确要用另一个空目录重新开始。这时不能只改个路径就宣称完成，需要：

1. 在 Sync 选好新的空目录并确认。
2. 到格间明确同意，准备「当前本机内容的完整备份」。这个整体备份也叫“快照”。
3. Sync 上传快照，逐个读回加密对象，检查大小和内容是否与可信清单一致。
4. 全部通过，再把保存位置切换到新目录，同时写入「新备份已建立」记录。

本轮优化后，第 4 步完成就结束这次操作，不再立刻附加一次普通同步。准备快照之后新增或修改的内容，在下一轮备份处理；需要马上备份这些后续变化时，可以返回首页再点「立即备份」。

新备份不会主动删除旧目录，也无法找回“只剩在丢失的云端、本机也已经没有”的内容。它不能重新生成已经丢失的旧版本历史。

## 六、换手机后怎样恢复？

**找到原备份 → 找回原账号 → 授权新设备 → 下载并检查 → 格间解密和还原 → 确认完成。**

1. **选择原来的云端连接和备份目录。** 恢复时不能随便选一个新空目录。
2. **在格间找回原账号。** 使用相应的恢复卡流程；如果使用需要云端加密恢复文件的纸卡方式，先由 Sync 取回这个加密文件，再交给格间。旧备份没有该文件时，需要旧卡的完整恢复方式，或原设备补齐。
3. **让格间授权新设备的 Sync。** 能登录 NAS，不等于已经有权恢复格间账号。
4. **Sync 查找并验证备份。** 检查来源、必要历史和附件，把可信的加密内容取回。
5. **回到格间解锁并确认恢复。** 真正的解密、写入账号/文件/照片等业务数据，在格间完成。存在冲突或缺失时按提示处理。
6. **格间确认实际应用完成，再与 Sync 完成状态交接。** 对完整快照恢复，包含真实写入、内容读回和签名完成回执。只有下载结束，不能说整个恢复已经完成。

恢复后也应打开重要文件正文、照片原图和账号详情确认；看到列表标题或缩略图，不等于正文已经可用。文档数据与手机端是否提供对应展示入口，也是两回事。

## 七、怎样读懂记录？

| 显示内容 | 应怎样理解 |
|---|---|
| 无需传输 | 本轮没有新增业务对象需要传输；格间可能还未准备好新变化，也仍可能发生网络检查。 |
| 普通传输已完成 | 这次记录对应的传输运行完成；不能据此推断其他设备已解密并恢复所有内容。 |
| 新备份已建立 | 本次完整快照已上传并读回校验，新保存位置已切换。之后的改动另算。 |
| 请到格间完成恢复 | 加密内容已进入恢复流程，仍需要格间实际处理。 |
| 失败 | 查看具体原因；不能靠删历史、重置进度或重复新建空目录把它变成成功。 |

失败重试会保留安全检查。新位置完整快照中已存在的对象，会校验后再继续；这不等于大文件支持从断点接着上传。当前 WebDAV 大文件上传中断后，尚未完成的那个对象仍可能需要整份重传。

## 八、这次为什么优化，以及还剩什么限制？

这次减少了两类重复工作：成功写入后，同一连接对象不再对相同父目录反复发建目录请求；新完整备份保留一次逐对象读回校验，结束后不再重复整份校验并立即追加普通同步。

测试中，11 个对象、4 层父目录的建目录请求从原先 44 次降到 4 次。完整重建流程的全量读回从原先约三遍降到一遍。这是工作量的减少，实际等待时间还受网速、NAS 响应和数据量影响。

下一轮独立同步仍会重新验证远端；目前已有快照的配置，即使没有新内容，仍可能读取完整快照检查。因此本轮没有承诺“无变化就零网络流量”，也没有为了提速跳过签名、防覆盖或内容完整性检查。
